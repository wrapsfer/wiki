# Getting Started

Run the Wrapsfer API locally against PostgreSQL, Keycloak, and RabbitMQ, then
verify it works.

The full step-by-step is also tracked in the API repo at `SETUP.md`. This page
mirrors that flow at a higher level and points out the config the API
actually consumes.

## Prerequisites

- **.NET SDK 10.0.201** or a compatible 10.x feature SDK.
- **Docker** (for PostgreSQL, Keycloak, RabbitMQ — and optionally Redis).
- **Entity Framework Core CLI tools** for migrations:

  ```bash
  dotnet tool install --global dotnet-ef
  ```

Check the .NET install with `dotnet --info`.

## Start Local Infrastructure

The API expects PostgreSQL, Keycloak, and RabbitMQ to be reachable. The
quickest path on a developer machine uses individual `docker run` commands
on a shared network — see `SETUP.md` in the API repo for copy-pasteable
commands. The repo also ships a `compose.yaml` for the deployable stack.

What the API connects to:

| Component  | Default local URL              | Purpose                                                  |
| ---------- | ------------------------------ | -------------------------------------------------------- |
| PostgreSQL | `localhost:5432`               | Application data and audit log.                          |
| Keycloak   | `http://localhost:8180`        | JWT issuer for tenant realms (per-realm OIDC discovery). |
| RabbitMQ   | `localhost:5672` (mgmt `:15672`) | `products.export`, `waybills.export`, `wrapsfer.mail`.   |

The application database name expected by the API is `wrapsfer`; create it
once after Postgres is up:

```bash
docker exec postgres createdb -U vernon wrapsfer
```

## Configure The API

Local config goes through user secrets so passwords are not committed. From
the API repo root:

```bash
dotnet user-secrets set "ConnectionStrings:DefaultConnection" \
  "Host=localhost;Port=5432;Database=wrapsfer;Username=vernon;Password=password" \
  --project src/Wrapsfer.Api/Wrapsfer.Api.csproj

dotnet user-secrets set "Keycloak:BaseUrl" "http://localhost:8180" \
  --project src/Wrapsfer.Api/Wrapsfer.Api.csproj
dotnet user-secrets set "Keycloak:RequireHttpsMetadata" "false" \
  --project src/Wrapsfer.Api/Wrapsfer.Api.csproj

dotnet user-secrets set "RabbitMq:HostName" "localhost" \
  --project src/Wrapsfer.Api/Wrapsfer.Api.csproj
dotnet user-secrets set "RabbitMq:Port" "5672" \
  --project src/Wrapsfer.Api/Wrapsfer.Api.csproj
dotnet user-secrets set "RabbitMq:UserName" "vernon" \
  --project src/Wrapsfer.Api/Wrapsfer.Api.csproj
dotnet user-secrets set "RabbitMq:Password" "password" \
  --project src/Wrapsfer.Api/Wrapsfer.Api.csproj
dotnet user-secrets set "RabbitMq:VirtualHost" "/" \
  --project src/Wrapsfer.Api/Wrapsfer.Api.csproj
```

`appsettings.json` ships sensible defaults for `Keycloak:OwnerRealm = "owner"`
and `Keycloak:Audience = "wrapsfer-api"`. The Resend API key
(`Mailing:Resend:ApiKey`) is required by `Wrapsfer.Mailing` startup
validation; for local-only flows where you do not actually send email,
set a placeholder via user secrets to satisfy the `ValidateOnStart` check.

Full configuration reference is in
[Configuration](../maintainers/configuration).

## Restore, Build, Test

```bash
make restore
make build
make test
```

Equivalent commands without Make:

```bash
dotnet restore
dotnet build --no-restore
dotnet test --no-restore --no-build
```

## Apply Database Migrations

`ApplicationDbContextFactory` reads the design-time connection string from
the `WRAPSFER_DESIGN_CONNECTION` environment variable; if unset, it falls
back to `Host=localhost;Port=5432;Database=wrapsfer;Username=postgres;Password=postgres`.
Set the env var so it matches your local Postgres credentials before
running migrations:

```bash
export WRAPSFER_DESIGN_CONNECTION="Host=localhost;Port=5432;Database=wrapsfer;Username=vernon;Password=password"

dotnet ef database update \
  --project src/Wrapsfer.Infrastructure/Wrapsfer.Infrastructure.csproj \
  --startup-project src/Wrapsfer.Api/Wrapsfer.Api.csproj
```

For migration commands and the current migration list, see
[Database & Migrations](../maintainers/database-migrations).

## Run The API

```bash
dotnet run --project src/Wrapsfer.Api/Wrapsfer.Api.csproj
```

`launchSettings.json` defines two profiles, both with
`ASPNETCORE_ENVIRONMENT=Development`:

| Profile | URLs                                            |
| ------- | ----------------------------------------------- |
| `http`  | `http://0.0.0.0:5222`                           |
| `https` | `https://0.0.0.0:7065;http://0.0.0.0:5222`      |

`dotnet run` uses the **first** profile (`http`) by default. To pin a port
explicitly:

```bash
ASPNETCORE_URLS=http://localhost:8080 \
  dotnet run --project src/Wrapsfer.Api/Wrapsfer.Api.csproj --no-launch-profile
```

The `compose.yaml` deployment stack (`API_PORT`, default `8080`) maps a
different port than the local launch profile. Use whichever the binary
actually printed at startup.

## Smoke Test

For the default `http` launch profile (`http://localhost:5222`):

```bash
curl http://localhost:5222/health
curl http://localhost:5222/openapi/v1.json
```

`/health` aggregates the Npgsql and RabbitMQ health checks registered in
`ServiceCollectionExtensions.AddServices`; expect `Healthy` once both are
reachable. `/openapi/v1.json` is mapped only when the host is in
`Development`.

To call any business endpoint, supply a Keycloak JWT for an existing realm
and either set the realm via header or use a subdomain host name:

```bash
curl -H "Authorization: Bearer $TOKEN" \
     -H "X-Tenant-Realm: acme" \
     http://localhost:5222/api/v1/me
```

See [Authentication & Tenancy](./authentication-tenancy) for the full
contract, including the owner-realm `tenantId` query parameter rule.

## Bruno Collection

The API repo ships a [Bruno](https://www.usebruno.com) collection at
`bruno/` with `Auth/`, `Me/`, and `Products/` folders. Pair it with one of
the environments under `bruno/environments/` — set the `baseUrl` and the
JWT/realm variables, then exercise the endpoints. The collection does not
cover every controller; treat it as a starter, not a contract source.
