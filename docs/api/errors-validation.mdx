# Errors & Validation

The Wrapsfer API returns errors as
[`ProblemDetails`](https://datatracker.ietf.org/doc/html/rfc7807) JSON. Two
paths produce them: the `ApiControllerBase` `Result`-to-HTTP mapping for
domain failures, and the global `UseExceptionHandler` for unhandled
exceptions. Both add a `traceId` extension that matches
`HttpContext.TraceIdentifier` for the request.

All error responses carry `Content-Type: application/problem+json`.

## Result → HTTP Mapping

Commands and queries return `Result` or `Result<T>` from the domain. The
controller helpers `ToActionResult` and `ToCreatedResult` map them:

| `Result.Error.Type`     | Status | Notes                                                        |
| ----------------------- | ------ | ------------------------------------------------------------ |
| `ErrorType.NotFound`    | `404`  | `NotFound` `ProblemDetails` body.                            |
| `ErrorType.Validation`  | `400`  | `BadRequest` `ProblemDetails` body.                          |
| `ErrorType.Conflict`    | `409`  | `Conflict` `ProblemDetails` body.                            |
| `ErrorType.Failure` / other | `400`  | Default fallback for any other failure error type.       |

Each response uses the domain `Error.Code` as the `title` and `Error.Description`
as the `detail`:

```json
HTTP/1.1 404 Not Found
Content-Type: application/problem+json

{
  "status": 404,
  "title": "Product.NotFound",
  "detail": "The requested product was not found."
}
```

Successful `Result` outcomes return:

- `200 OK` with the value for `Result<T>` from `ToActionResult`.
- `204 No Content` for `Result` from `ToActionResult`.
- `201 Created` for `Result<T>` from `ToCreatedResult` (route name and
  values optional).

## Validation Errors From Model Binding

ASP.NET Core model-state validation failures (e.g. malformed JSON, missing
`[Required]` fields, route constraint mismatches) are intercepted by
`ConfigureApiBehaviorOptions.InvalidModelStateResponseFactory` in
`ServiceCollectionExtensions.AddServices`. The response body has shape:

```json
HTTP/1.1 400 Bad Request
Content-Type: application/problem+json

{
  "status": 400,
  "title": "Validation Error",
  "detail": "One or more fields in the request body are invalid.",
  "errors": {
    "Cost": ["The Cost field is required."],
    "Type": ["The JSON value could not be converted to ProductType."]
  },
  "traceId": "0HMV2..."
}
```

When a JSON deserialization error coexists with a "field is required" error
on the parent parameter, the helper drops the misleading top-level
"command field is required" message so the actual failing field surfaces.

FluentValidation failures from `ValidationBehavior<TRequest, TResponse>`
return through the `Result` path as `ErrorType.Validation` (`400`).

## Global Exception Handler

`Wrapsfer.Api.Extensions.WebApplicationExtensions.ConfigurePipeline` wraps the
pipeline in `UseExceptionHandler`. The handler classifies the unhandled
exception, logs it server-side, and emits a `ProblemDetails` body with a
`traceId` extension:

| Status | Title                  | Trigger                                                                                    |
| ------ | ---------------------- | ------------------------------------------------------------------------------------------ |
| `401`  | `Authentication Error` | `InvalidOperationException` with message `"Tenant realm has not been resolved."`           |
| `401`  | `Authentication Error` | `InvalidOperationException` with message `"User is not authenticated."`                    |
| `400`  | `Invalid Argument`     | `ArgumentException`.                                                                       |
| `503`  | `Configuration Error`  | `InvalidOperationException` whose message contains `"not configured"`.                     |
| `503`  | `Database Error`       | Any `Npgsql`/`PostgresException` reachable through the inner-exception chain.              |
| `504`  | `Request Timeout`      | `TimeoutException`.                                                                        |
| `500`  | `Internal Server Error`| Anything else (including `null` exception state).                                          |

Database errors are further classified by Postgres `SqlState`:

- `42P01` (relation does not exist) and `42703` (column does not exist)
  produce the same `503` with a "Run pending migrations." detail.
- `28P01` (invalid password) produces a "Database authentication failed.
  Check connection credentials." detail.
- A `SocketException` anywhere in the chain produces a "Cannot reach the
  database server. Ensure PostgreSQL is running." detail.
- Anything else gets a generic detail and the exception is logged.

The handler never includes raw stack traces or driver messages in the
response body — those go to the structured Serilog logs.

## JSON Conventions

- **Enums are strings.** `JsonStringEnumConverter` is registered globally
  in `AddJsonOptions`, so `ProductType`, `WaybillStatus`, `StockAlertType`,
  `StockAlertDeliveryStatus`, and `ProductFileFormat` serialize and
  deserialize as their string names (`"Single"`, `"Draft"`, `"LowStock"`,
  `"Csv"`, etc.).
- **Property names are camelCase** in responses (ASP.NET Core defaults).

## Common Error Codes

A non-exhaustive sample of domain error codes you can expect to encounter
on the wire (full list lives in `Wrapsfer.Domain.Errors.*`):

| Code                                    | Type        | Status | When                                                       |
| --------------------------------------- | ----------- | ------ | ---------------------------------------------------------- |
| `Product.NotFound`                      | NotFound    | `404`  | Product lookup misses.                                     |
| `Product.BarcodeAlreadyExists`          | Conflict    | `409`  | Barcode collides within tenant.                            |
| `Product.InvalidStockChange`            | Validation  | `400`  | Stock mutation breaks an invariant.                        |
| `Product.BundleHasNoComponents`         | Validation  | `400`  | Reservation against an empty Bundle.                       |
| `ProductImport.FileRequired`            | Validation  | `400`  | `IFormFile` missing or empty.                              |
| `ProductImport.FileTooLarge`            | Validation  | `400`  | Upload over 20 MB.                                         |
| `ProductImport.UnsupportedFormat`       | Validation  | `400`  | Content type not allowed for the chosen format.            |
| `Waybill.NotFound`                      | NotFound    | `404`  | Waybill lookup misses.                                     |
| `Waybill.CannotEditNonDraft`            | Validation  | `400`  | Mutating a waybill outside `Draft`.                        |
| `Waybill.InvalidStatusTransition`       | Validation  | `400`  | Illegal status transition (e.g. cancel already cancelled). |
| `Waybill.CancellationReasonRequired`    | Validation  | `400`  | Cancel without a non-empty reason.                         |
| `Waybill.NotWaybillCreator`             | Validation  | `400`  | Hand-off attempted by a user other than the creator.       |
| `TenantSettings.RecipientAlreadyExists` | Conflict    | `409`  | Adding a recipient email that already exists.              |
| `TenantSettings.InvalidEmail`           | Validation  | `400`  | Recipient email rejected by the simple format check.       |

For module-specific examples, see the [Products](./products) and
[Waybills](./waybills) pages.
