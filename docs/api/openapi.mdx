# OpenAPI Specification

The Wrapsfer API ships a generated OpenAPI document via
`Microsoft.AspNetCore.OpenApi`. The endpoint is gated behind
`Development` so it is reachable on local and Compose flows but not on a
production deployment.

## How It Is Wired

In `src/Wrapsfer.Api/Extensions/ServiceCollectionExtensions.cs`:

```csharp
builder.Services.AddOpenApi();
```

In `src/Wrapsfer.Api/Extensions/WebApplicationExtensions.cs`:

```csharp
if (app.Environment.IsDevelopment())
{
    app.MapOpenApi();
}
```

- **`AddOpenApi()`** registers the OpenAPI document generator and the
  versioned API explorer (because `AddApiVersioning().AddApiExplorer(...)`
  also runs at startup, with `SubstituteApiVersionInUrl = true`).
- **`MapOpenApi()`** adds the HTTP endpoint that serves the document.
  Only mapped when `ASPNETCORE_ENVIRONMENT=Development`.

No custom document title, version, server, or security scheme is wired
in source today. The output reflects whatever the API
versioning + OpenAPI integration produces from the registered
controllers — which means, currently, the v1 surface for `me`,
`products`, `waybills`, `tenant-settings`, and `stock-alerts`.

## The Endpoint

| Method | Path                | Availability             |
| ------ | ------------------- | ------------------------ |
| `GET`  | `/openapi/v1.json`  | **`Development` only**   |

In `Development`:

```bash
curl -i http://localhost:5222/openapi/v1.json
```

Returns `200 OK` with `Content-Type: application/json` containing the
OpenAPI v1 document. Outside `Development`, the route is not mapped and
returns `404 Not Found`.

The default launch profiles in
`src/Wrapsfer.Api/Properties/launchSettings.json` set
`ASPNETCORE_ENVIRONMENT=Development`, so the endpoint is reachable in
both `http` and `https` local profiles.

## Common Uses

- **Endpoint discovery.** Render the document with Swagger UI, Redoc,
  or an IDE HTTP client to browse routes and try requests.
- **Client generation.** Feed the document to a generator
  (`openapi-generator`, `Kiota`, `NSwag`) to produce typed clients
  in TypeScript, C#, Python, etc.
- **Contract checks.** Diff successive versions in CI to surface
  breaking changes to the public surface.
- **Bruno collection seed.** Use the document to scaffold or update
  the request collection that ships under `bruno/` in the API repo.

## What The Document Does Not Capture

A few behaviors are encoded outside controller signatures and therefore
do not appear directly in the schema:

- **Owner-realm `tenantId` query.** Enforced by `TenantResolutionFilter`,
  not by an explicit `[FromQuery]` parameter on each action — see
  [Authentication & Tenancy](./authentication-tenancy).
- **Authentication.** The bearer requirement comes from `[Authorize]`
  on `ApiControllerBase`. No security scheme is configured in the
  OpenAPI document today; clients must add the `Authorization` header
  manually.
- **Per-`Result` error mappings.** The HTTP status codes returned
  by `ToActionResult` (`200`/`201`/`204` on success; `400`/`404`/`409`
  on failure) are not declared via `[ProducesResponseType]` per action —
  see [Errors & Validation](./errors-validation) for the full contract.

## Production Exposure

OpenAPI is **not** exposed outside `Development` unless
`WebApplicationExtensions.ConfigurePipeline` is intentionally changed.
Promoting to `Staging` or `Production` (by setting
`ASPNETCORE_ENVIRONMENT` accordingly) silently removes the endpoint.

If exposing it beyond local becomes desirable, decide alongside:

- whether the document should sit behind authentication,
- whether to publish a static, versioned artifact instead of a live
  endpoint,
- whether to restrict CORS / network access to the route,
- whether to add `[ProducesResponseType]` and security scheme metadata
  to make the document self-describing.

Until that decision is made, treat the absence of `/openapi/v1.json`
outside `Development` as intentional.
