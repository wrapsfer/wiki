# Configuration

Every configuration section the Wrapsfer API actually consumes today,
where it is bound, and what is required vs. optional.

The application is built with `WebApplication.CreateBuilder(args)` and then
composes configuration through `AddServices`, `AddApplication`,
`AddInfrastructure`, and `AddMailing`. Sources follow standard ASP.NET
Core precedence: `appsettings.json` → `appsettings.{Environment}.json` →
user secrets (Development) → environment variables → command-line.

## Connection Strings

```json
"ConnectionStrings": {
  "DefaultConnection": "Host=...;Port=...;Database=wrapsfer;Username=...;Password=..."
}
```

| Key                                 | Required | Notes                                                       |
| ----------------------------------- | -------- | ----------------------------------------------------------- |
| `ConnectionStrings:DefaultConnection` | yes    | PostgreSQL connection string. Failure to configure throws on startup (`AddInfrastructure` and the Npgsql health check). |

A separate environment variable, `WRAPSFER_DESIGN_CONNECTION`, is read by
`ApplicationDbContextFactory` for `dotnet ef` operations only — it is not
consumed by the running API.

## `Keycloak`

Bound to `KeycloakOptions` (`Wrapsfer.Infrastructure.Authentication`)
with `KeycloakOptionsValidator` validating on start.

```json
"Keycloak": {
  "BaseUrl": "https://auth.domain.com",
  "OwnerRealm": "owner",
  "Audience": "wrapsfer-api",
  "RequireHttpsMetadata": true
}
```

| Key                              | Type    | Required | Default          | Notes                                                                |
| -------------------------------- | ------- | -------- | ---------------- | -------------------------------------------------------------------- |
| `Keycloak:BaseUrl`               | string  | yes      | —                | Keycloak root URL (no realm path).                                   |
| `Keycloak:OwnerRealm`            | string  | yes      | `"owner"`        | Owner realm name. Determines who needs `?tenantId=...`.              |
| `Keycloak:Audience`              | string  | yes      | `"wrapsfer-api"` | JWT `aud` claim expected by the bearer scheme.                       |
| `Keycloak:RequireHttpsMetadata`  | bool    | no       | `true`           | Set to `false` for local Keycloak over HTTP.                         |

## `RabbitMq`

Used by both `Wrapsfer.Infrastructure.Queue.RabbitMqOptions` (the API's
publisher and consumers) and `Wrapsfer.Mailing.Queue.RabbitMqOptions`
(the mailing queue). The two `RabbitMqOptions` classes bind from the
same `RabbitMq` section.

```json
"RabbitMq": {
  "HostName": "localhost",
  "Port": 5672,
  "UserName": "vernon",
  "Password": "password",
  "VirtualHost": "/"
}
```

| Key                       | Type   | Required | Default   |
| ------------------------- | ------ | -------- | --------- |
| `RabbitMq:HostName`       | string | yes      | —         |
| `RabbitMq:Port`           | int    | yes      | `5672`    |
| `RabbitMq:UserName`       | string | yes      | —         |
| `RabbitMq:Password`       | string | yes      | —         |
| `RabbitMq:VirtualHost`    | string | no       | `"/"`     |

`AddServices` constructs an `Npgsql` health check and a `RabbitMQ` health
check using the same configuration; missing keys fail at startup with
an `InvalidOperationException` rather than silently falling back to
`guest`/`guest`.

## `Mailing`

Bound across `ResendOptions`, `MailQueueOptions`, and
`Wrapsfer.Mailing.Queue.RabbitMqOptions`. Validators in
`Wrapsfer.Mailing.DependencyInjection` enforce the required values.

```json
"Mailing": {
  "Resend": {
    "ApiKey": "",
    "FromAddress": "noreply@wrapsfer.store",
    "FromName": "Wrapsfer"
  },
  "Queue": {
    "QueueName": "wrapsfer.mail",
    "MaxRetries": 3,
    "InitialBackoffSeconds": 1
  }
}
```

| Key                                 | Type   | Required | Default                  | Notes                                                          |
| ----------------------------------- | ------ | -------- | ------------------------ | -------------------------------------------------------------- |
| `Mailing:Resend:ApiKey`             | string | yes      | —                        | Validated on start; cannot be empty.                           |
| `Mailing:Resend:FromAddress`        | string | yes      | `"noreply@wrapsfer.store"` | Sender. Validated on start.                                  |
| `Mailing:Resend:FromName`           | string | no       | `"Wrapsfer"`             | Sender display name.                                           |
| `Mailing:Queue:QueueName`           | string | no       | `"wrapsfer.mail"`        | RabbitMQ queue name for outbound mail.                         |
| `Mailing:Queue:MaxRetries`          | int    | no       | `3`                      | Used by `MailRetryPolicy`.                                     |
| `Mailing:Queue:InitialBackoffSeconds` | int  | no       | `1`                      | Exponential backoff base (seconds).                            |

For local-only flows that do not actually deliver email, set
`Mailing:Resend:ApiKey` to a placeholder string (e.g. via user secrets)
to satisfy the `ValidateOnStart` check.

## `ProductSettings`

Bound to `Wrapsfer.Application.Products.ProductSettings`.

```json
"ProductSettings": { "GlobalLowStockThreshold": 10 }
```

| Key                                       | Type | Default | Notes                                                                              |
| ----------------------------------------- | ---- | ------- | ---------------------------------------------------------------------------------- |
| `ProductSettings:GlobalLowStockThreshold` | int  | `10`    | Fallback when neither the product's nor the tenant's threshold is set.             |

## `Infisical`

Bound to `Wrapsfer.Infrastructure.Configuration.InfisicalOptions`.
Optional — when configured, secrets are loaded into the configuration
provider chain on startup by `InfisicalSecretProvider`.

```json
"Infisical": {
  "ClientId": "",
  "ClientSecret": "",
  "ProjectId": "",
  "HostUri": "https://app.infisical.com",
  "Environment": "dev",
  "SecretPath": "/"
}
```

| Key                       | Required | Default                     | Notes                                                       |
| ------------------------- | -------- | --------------------------- | ----------------------------------------------------------- |
| `Infisical:ClientId`      | only when used | —                     | If section is present, all three secrets are required.      |
| `Infisical:ClientSecret`  | only when used | —                     | Sensitive — never put in committed JSON.                    |
| `Infisical:ProjectId`     | only when used | —                     |                                                             |
| `Infisical:HostUri`       | no       | `"https://app.infisical.com"` | Self-hosted Infisical URL goes here.                      |
| `Infisical:Environment`   | no       | `"dev"`                     | Infisical environment slug.                                 |
| `Infisical:SecretPath`    | no       | `"/"`                       | Secret folder path within the project.                      |

Treat the entire section as optional — when omitted, the API runs without
the Infisical provider.

## `Serilog`

Wrapsfer logs through Serilog. Configuration is read from the `Serilog`
section by `LoggerConfiguration.ReadFrom.Configuration`, registered in
`AddServices`. The default configuration uses a console sink.

```json
"Serilog": {
  "Using": ["Serilog.Sinks.Console"],
  "MinimumLevel": {
    "Default": "Information",
    "Override": {
      "Microsoft.AspNetCore": "Warning",
      "Microsoft.EntityFrameworkCore": "Warning"
    }
  },
  "WriteTo": [
    { "Name": "Console", "Args": { "outputTemplate": "[{Timestamp:HH:mm:ss} {Level:u3}] {SourceContext}{CorrelationId: [{CorrelationId}]} {Message:lj}{NewLine}{Exception}" } }
  ],
  "Enrich": ["FromLogContext", "WithMachineName", "WithThreadId"]
}
```

To add a sink (e.g. Seq, Elasticsearch), add the package to
`Wrapsfer.Api.csproj`, list it under `Using`, and add a `WriteTo` entry.
The `Serilog.Settings.Configuration` package handles the rest.

## Environment Variable Reference

ASP.NET Core uses double underscores for nested keys. Common overrides:

| Configuration key                      | Environment variable                          |
| -------------------------------------- | --------------------------------------------- |
| `ConnectionStrings:DefaultConnection`  | `ConnectionStrings__DefaultConnection`        |
| `Keycloak:BaseUrl`                     | `Keycloak__BaseUrl`                           |
| `Keycloak:OwnerRealm`                  | `Keycloak__OwnerRealm`                        |
| `Keycloak:Audience`                    | `Keycloak__Audience`                          |
| `Keycloak:RequireHttpsMetadata`        | `Keycloak__RequireHttpsMetadata`              |
| `RabbitMq:HostName`                    | `RabbitMq__HostName`                          |
| `RabbitMq:Port`                        | `RabbitMq__Port`                              |
| `RabbitMq:UserName`                    | `RabbitMq__UserName`                          |
| `RabbitMq:Password`                    | `RabbitMq__Password`                          |
| `Mailing:Resend:ApiKey`                | `Mailing__Resend__ApiKey`                     |
| `Mailing:Resend:FromAddress`           | `Mailing__Resend__FromAddress`                |
| `ProductSettings:GlobalLowStockThreshold` | `ProductSettings__GlobalLowStockThreshold` |

Two ASP.NET Core host variables:

| Variable                  | Purpose                                                  |
| ------------------------- | -------------------------------------------------------- |
| `ASPNETCORE_ENVIRONMENT`  | Controls `app.Environment.IsDevelopment()` and which `appsettings.{Environment}.json` is loaded. |
| `ASPNETCORE_URLS`         | Bind addresses (e.g. `http://+:8080` for containers).    |

## Required vs. Local-Only Values

| Value                                   | Required in production? | Local default OK? | Notes                                          |
| --------------------------------------- | ----------------------- | ----------------- | ---------------------------------------------- |
| `ConnectionStrings:DefaultConnection`   | yes                     | yes (per setup)   | Must point at PostgreSQL.                      |
| `Keycloak:BaseUrl`                      | yes                     | yes               |                                                |
| `Keycloak:RequireHttpsMetadata`         | yes (`true`)            | `false` for HTTP local Keycloak | Default is `true`.                |
| `RabbitMq:*`                            | yes                     | yes               |                                                |
| `Mailing:Resend:ApiKey`                 | yes                     | placeholder OK    | Validated; placeholder satisfies the check.    |
| `Mailing:Resend:FromAddress`            | yes                     | yes               |                                                |
| `ProductSettings:GlobalLowStockThreshold` | no                    | yes (`10`)        | Tenant or per-product values usually win.      |
| `Infisical:*`                           | no                      | yes               | Section is optional.                           |
| `Serilog:*`                             | optional sinks          | yes               | Console sink ships by default.                 |

Never commit real secrets into `appsettings*.json`. Use user secrets
locally, environment variables in containers, and a secrets backend
(Infisical, AWS Secrets Manager, etc.) in production.
