# Development Workflow

How to add a feature to the Wrapsfer API while keeping the layer
boundaries, CQRS conventions, and tenant isolation rules intact. The
**Products** module under `Wrapsfer.Application/Products/` is the
canonical reference; new modules should mirror its layout.

For high-level layer responsibilities, see [Architecture](./architecture).

## End-To-End Flow For A New Use Case

1. **Domain** (`Wrapsfer.Domain`)
   - Add or update an aggregate root in `Domain/Entities/`.
   - Encode invariants in private constructors and factory methods that
     return `Result<T>` or `Result`. Mutators that can fail also return
     `Result` — never `void`.
   - Define every error as a `static readonly Error` on a per-aggregate
     class in `Domain/Errors/` (e.g. `ProductErrors.NotFound`). Inline
     `new Error(...)` is forbidden.
   - Raise domain events through `BaseEntity.AddDomainEvent(...)` for
     anything that needs side-effects (`LowStockDetectedEvent`,
     `WaybillPackedEvent`, etc.).
   - Add a repository interface to `Domain/Repositories/` if you need
     persistence. Every method must accept `tenantId`.

2. **Application** (`Wrapsfer.Application`)
   - For each command, create a folder
     `Application/{Module}/Commands/{CommandName}/` with three files:
     - `{CommandName}Command.cs` — `public sealed record …Command(…) : ICommand<TResult>;`
     - `{CommandName}CommandHandler.cs` — `internal sealed class … : ICommandHandler<…>`
     - `{CommandName}CommandValidator.cs` — `AbstractValidator<…>`.
   - Same shape for queries under `Queries/`.
   - Reach for `ITenantContext.TenantId` whenever you need the acting
     tenant; never trust untrusted query strings or claims directly in
     handlers.
   - Use the constructor-injected `IUnitOfWork` to commit. Repositories
     are also constructor-injected.
   - Domain event handlers go under `Application/{Module}/EventHandlers/`
     and implement `IDomainEventHandler<TEvent>`.
   - Response DTOs (`{X}Response`) belong in `Application/{Module}/Responses/`.

3. **Infrastructure** (`Wrapsfer.Infrastructure`)
   - Implement the repository interface under
     `Infrastructure/Persistence/Repositories/` and add an EF
     `IEntityTypeConfiguration<T>` under
     `Infrastructure/Persistence/Configurations/`.
   - Always include a `tenant_id` filter and `(tenant_id, ...)` indexes
     in the EF configuration; rely on tenant filtering in code rather
     than global query filters.
   - Register the repository in
     `Infrastructure.DependencyInjection.AddInfrastructure`.
   - For new options classes (`Foo`), define `public const string SectionName`
     and bind via `services.Configure<Foo>(configuration.GetSection(Foo.SectionName))`.

4. **API** (`Wrapsfer.Api`)
   - Add a controller in `Controllers/V1/` that inherits
     `ApiControllerBase` (gives you `[Authorize]`, route prefix, API
     versioning, and `ToActionResult`/`ToCreatedResult`).
   - Apply `[ServiceFilter(typeof(TenantResolutionFilter))]` whenever
     owner-realm impersonation should apply (it usually should).
   - Define request DTOs in `Contracts/`. Map to MediatR commands inside
     the action.
   - Forward through `ISender.Send(...)` and pipe the `Result` through
     the helpers — controllers stay 4–10 lines per action.

5. **Tests** (`tests/`)
   - Add domain tests for invariants (`Wrapsfer.Domain.Tests`).
   - Add handler/validator tests for happy/failure paths
     (`Wrapsfer.Application.Tests`).
   - Add an integration test if the endpoint is publicly observable
     (`Wrapsfer.IntegrationTests`).

## Coding Rules (From `CLAUDE.md` In The API Repo)

These project-wide rules influence almost every change:

- **Never use `var`.** Always declare explicit types. Enforced by the
  pre-commit hook and `dotnet format style`.
- **One type per file.** Every class, record, struct, enum, and
  interface gets its own file.
- **No consecutive blank lines** (max 1). Enforced by the pre-commit hook.
- **`TreatWarningsAsErrors` is on globally** — warnings fail the build.
- **Field naming.** `_camelCase` for private/internal fields,
  `s_camelCase` for static fields, `PascalCase` for constants.
- **Nullable reference types** are enabled globally.
- **Tenant isolation.** Every repository method that reads or mutates
  tenant data MUST take and filter by `tenantId`. Never query by ID
  alone.
- **Domain validation.** Domain factories and mutators that can fail MUST
  return `Result` / `Result<T>` — never `void`.
- **Concurrency control.** Entities with concurrent-update fields
  (e.g. stock quantities) must declare a concurrency token (`xmin` for
  PostgreSQL) in their EF configuration.
- **No N+1 queries.** Use batch repository methods (`GetByIdsAsync`,
  `GetByBarcodesAsync`).
- **No internal details in API responses.** The exception handler must
  not leak DB messages, stack traces, or configuration values to the
  client. Log details server-side; return generic messages.
- **No silent fallback credentials.** Infrastructure config must throw
  on missing keys (no `?? "guest"`).
- **Collection encapsulation.** Domain collection navigation
  properties expose `IReadOnlyCollection<T>` over a private `List<T>`.

## DI Registration Locations

| Registration                                 | File                                                                |
| -------------------------------------------- | ------------------------------------------------------------------- |
| MediatR + behaviors + validators             | `Wrapsfer.Application.DependencyInjection.AddApplication`           |
| EF Core, repositories, interceptors, queue, file processing, hosted services | `Wrapsfer.Infrastructure.DependencyInjection.AddInfrastructure` |
| Mailing module (publisher, consumer, templates, options) | `Wrapsfer.Mailing.DependencyInjection.AddMailing`        |
| Controllers, OpenAPI, health checks, JSON options, API versioning | `Wrapsfer.Api.Extensions.ServiceCollectionExtensions.AddServices` |

`Program.cs` composes them in order. Add new registrations next to the
existing ones; do not register layer-specific services directly in
`Program.cs`.

## Pre-Commit Quality Sequence

```bash
make restore
make build           # warnings = build failures
make test
make format-all      # whitespace + style fixes (dotnet format + dotnet format style)
```

The pre-commit hook runs format checks and rejects commits that
introduce `var` or consecutive blank lines.

## Adding A New Database Migration

1. Make the entity / configuration / DbSet changes.
2. From the API repo root:

   ```bash
   export WRAPSFER_DESIGN_CONNECTION="Host=localhost;Port=5432;Database=wrapsfer;Username=vernon;Password=password"

   dotnet ef migrations add <DescriptiveName> \
     --project src/Wrapsfer.Infrastructure/Wrapsfer.Infrastructure.csproj \
     --startup-project src/Wrapsfer.Api/Wrapsfer.Api.csproj
   ```

3. Apply locally to verify:

   ```bash
   dotnet ef database update \
     --project src/Wrapsfer.Infrastructure/Wrapsfer.Infrastructure.csproj \
     --startup-project src/Wrapsfer.Api/Wrapsfer.Api.csproj
   ```

4. Commit the generated migration files together with the code changes.
   Never hand-edit `ApplicationDbContextModelSnapshot.cs`.

See [Database & Migrations](./database-migrations) for the full CLI
reference.

## Adding A New RabbitMQ Consumer

1. Define the message record next to the producer
   (`Application/{Module}/Messaging/{X}RequestedMessage.cs`) with
   `public const string QueueName = "...";`.
2. Implement the consumer as a `BackgroundService` in
   `Infrastructure/BackgroundServices/`.
3. Register with `services.AddHostedService<TConsumer>()` in
   `Infrastructure.DependencyInjection.AddInfrastructure`.
4. Use `RabbitMqMessagePublisher` (the singleton `IMessagePublisher`)
   from the producer side.
5. Add tests for both the publish and the consume path; mock
   `IMessagePublisher` in handler tests.

See [Messaging & Background Jobs](./messaging-background-jobs).

## Adding A New Email Template

1. Create `src/Wrapsfer.Mailing/Templates/Files/{name}/subject.liquid`,
   `body.html.liquid`, `body.text.liquid`.
2. Reference it from a caller via `MailMessage.TemplateName = "name"`
   plus `Tokens` for the Liquid variables.
3. Add a renderer test in `Wrapsfer.Mailing.Tests` to lock the template
   output for a representative token set.

See [Mailing](./mailing).

## Cross-Cutting Reminders

- The exception handler will translate `InvalidOperationException("...
  not configured")` into a `503 Configuration Error`. Use this pattern
  when fail-fast configuration validation is needed (rather than a
  fallback default).
- Any domain rule that emits user-visible feedback should be expressed
  as an `Error` constant — keeps wire codes stable and avoids drift in
  validation messages.
- When adding a controller, decide whether `MeController`-style
  bare auth or `ProductsController`-style auth + tenant filter applies.
  Owner-realm controllers that act on global state would not use the
  filter.
